## Assumptions / decisions flagged
1. **No Tailwind build exists** (plain CSS custom properties app-wide; nothing
   in package.json). The card's "map tokens into Tailwind config" is satisfied
   by the alias layer in globals.css — one rename point per role, which is the
   property a Tailwind `theme.extend.colors` map would provide. Adding Tailwind
   is a new dependency (Daedalus approval required) — NOT done.
2. **`.form-notice` (success flash) is now neutral** (canvas bg, ink-900 text,
   3px brand edge): the legacy green reused the *passed* status colour for a
   non-status message (§1.1 violation) and failed 4.5:1 anyway (3.81). Same
   treatment as `.banner-warning`/`.badge-*` (attention via brand/ink, not
   reserved status colours).
3. **Dead aliases removed**: `--warn/--warn-bg/--ok/--ok-bg` had no consumers
   after (2). Status colours remain reachable app-wide under their §2.2 names.
4. **Dark values beyond §2.3's literal list are placeholders** (ink-700/500,
   brand-hover/tint, status pairs, text-on-brand, scrim/shadow) — token names
   all flip correctly; values must be tuned to the §8 floor in the phase-2 pass.
5. Kept the pre-existing dirty `web/next.config.ts` (dev CORS proxy) and
   `server/tmp_check_pw.js` out of my commits — not mine, left as-was.

## Open risks
- `--line` (#DCE1E9) input borders are 1.3:1 vs the §8 3:1 UI floor — the
  literal §2.1 spec value; resting borders on flat surfaces are widely treated
  as exempt, and identification is carried by the 2px --brand focus ring
  (9.1:1), but this is a Daedalus call (darken the line token, or document the
  exemption). Row dividers are separators (not identification) — not affected.
- Dark placeholders are unproven against the §8 floor until the phase-2 pass
  (card says tokens only; no UI switch ships, §11).
- The .form-notice visual change is deliberate but new — reviewers who expect
  the old green flash should read assumption 2 before flagging it.
